## 1. 问题与约束

接手时项目的状态是"部分功能可用"：四个效果组件带着自己的 CSS 活着，其余全靠 Tailwind 工具类——而 Tailwind 从未安装。

约束有三条：

- **不能换栈**：React + Vite 是既成事实，重写没有收益；
- **必须留住效果组件**：它们是这个项目的起点，也是最贵的资产；
- **要有可验证的完成度**：不能再用"看起来能跑"作为验收标准。

<Callout type="warn" title="真实的起点">
`npm run build` 失败，`tsc -b` 退出码 2，渲染时 `ReferenceError` 直接白屏。而 `dist/` 是两天前的产物——我之前看到的"能跑"是缓存。
</Callout>

## 3. 结果

| 指标 | 前 | 后 |
| --- | --- | --- |
| 类型错误 | 13 | 0 |
| App.tsx | 407 行 | 30 行 |
| 构建 CSS | 11 KB（三行死指令） | 49 KB（真实工具类） |
| ESLint 警告 | 5 | 0 |

结构上，`App.tsx` 从"什么都干"变成纯编排，内容层从硬编码变成 MDX：

```text
src/
├─ App.tsx           # 路由表
├─ layout/           # 导航、页脚、命令面板
├─ pages/            # 7 个路由
├─ components/       # effects / mdx / notes / common / ui
└─ lib/content.ts    # 构建期索引
content/
├─ notes/*.mdx       # 6 篇
└─ retro/*.mdx       # 2 篇
```

## 4. 如果重来

只改一件事：**第一版就装 Tailwind。**

那 91 处工具类从第一天起就是死代码，而它们看起来完全正常。如果构建立刻失败，后面两周的所有工作都会建立在一个真的能用的样式层上，不会出现"这个是靠组件自带 CSS 撑起来的，那个是巧合"这种判断不清的状态。

<Callout type="unverified" title="待验证">
"依赖缺失应该让构建挂掉"这条我没找到通用做法。CSS 的 `@tailwind` 在语法上是合法的 at-rule，构建工具没有理由拒绝它。可能的方案是在 CI 里加一条断言：产物 CSS 中不得出现 `@tailwind` 字样。
</Callout>
